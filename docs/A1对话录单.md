## 运行层与权限

回合提交后立即返回编号，小程序按事件序号轮询。账号内最多一个运行回合，单进程最多四个。每轮最多八个工具调用，模型和图像工具共用 60 秒截止时间。进程重启时将遗留回合标为已中断。重新进入会话可恢复当前草稿的消息、卡片及运行中的回合。模型最近历史最多 20 条消息，草稿以 `read_draft` 读取的修订为准。

允许的工具为 `read_draft`、`list_customers`、`read_current_trip`、`edit_draft`、`import_image`、`ask_user`、`preview_trip`。正式确认走小程序直接调用 `/v1/trips/confirm`。清单里没有正式操作，运行层逐个校验工具名。金额仍由业务代码按整数分计算，缺单价用 `null`。提示词版本为 `a1-agent-v1`，复用图片提示词 `s7d-image-v3`。

`mergeOrder` 返回草稿或结构化核对项。旧文字和图片路由将核对项转回既有的 HTTP 422 和错误码。Agent 图片工具复用同一识别、去重、合并和迟到检查。Agent 编辑沿用账号事务与草稿修订，覆盖已填字段须有本轮明确回复。撤销时比较当前修订和该回合的结束修订，成功后用新修订恢复开始时的客户明细。

迁移 `010_agent.sql` 新增 `agent_turns`、`agent_messages`、`agent_events`。回合保存状态、草稿编号、起止修订及撤销快照。消息保存原文或回复和已选图片编号。事件保存进度、卡片、工具调用与模型统计。三张表均以 `account_id` 做行级隔离。改动事件和草稿写入一起提交。已确认或被表单修改的草稿会挡住旧的写入、撤销和确认。

表单与对话复用微信会话。同次会话离开手动表单时，未保存的草稿保留在小程序内存。再次打开表单时读取服务端最新草稿，修订不同会让配送员选择使用已保存版或保留本机修改。同一会话可在录单、取货和送货三个工作区标签间操作。

## 每趟指标

以有该账号权限的连接执行。替换 `$1` 为账号 UUID，`$2` 为草稿 UUID。使用应用角色时，先在同一事务中使用 `set_config('dispatch.account_id', …, true)` 设置账号。

```sql
WITH trip_events AS (
  SELECT * FROM dispatch.agent_events WHERE account_id = $1 AND draft_id = $2
), completed AS (
  SELECT e.turn_id, extract(epoch FROM (e.created_at - s.created_at)) AS seconds
  FROM trip_events e JOIN trip_events s USING (turn_id)
  WHERE e.kind = 'end' AND s.kind = 'submitted'
)
SELECT
  count(*) FILTER (WHERE kind = 'submitted') AS messages,
  count(*) FILTER (WHERE kind = 'card' AND payload->>'action' <> 'workspace') AS card_clicks,
  count(*) FILTER (WHERE kind = 'card' AND payload->>'action' = 'workspace') AS form_visits,
  count(*) FILTER (WHERE kind = 'undo') AS undo_successes,
  count(*) FILTER (WHERE kind = 'model') AS model_calls,
  coalesce(sum((payload->>'elapsedMs')::bigint) FILTER (WHERE kind = 'model'), 0) AS model_ms,
  coalesce(sum((payload->>'inputTokens')::bigint) FILTER (WHERE kind = 'model'), 0) AS input_tokens,
  coalesce(sum((payload->>'outputTokens')::bigint) FILTER (WHERE kind = 'model'), 0) AS output_tokens,
  (SELECT coalesce(round(sum(seconds) * 1000), 0) FROM completed) AS turn_wait_ms
FROM trip_events;
```

## A1 改版实现

配送 MVP 的标签依次是「助手、取货、送货、历史」。四页走同一微信会话并在显示时读取服务端数据。助手顶部展开草稿条后可进工作区手动改，按草稿修订核对本机未保存修改。取货和送货页通过 `pages/workspace/page.ts` 共用正式单加载与客户单操作，`trip-view.ts` 共用取货变化、实收和金额展示，S5 保留原工作区入口。送货页负责开始下一趟，仍未确认的客户名列在二次确认框里。

历史走 `GET /v1/trips` 分页，详情复用 `GET /v1/trips/{id}`。列表金额在服务端按现有配送规则算成整数分，待补价项单独统计。详情只读显示取货汇总、客户送货行、原订、实收、应收和送达状态。见[本地联调](S5本地联调.md#趟次历史)。

### 运行顺序与权限

方案 A 用一次 JSON 模式调用识别草稿、查询、预览及是否回答待答追问。涉及草稿的自由文字由模型另行整理，改草稿与出预览同轮时传入完整原话。草稿整理只允许调用 `edit_draft`、`ask_user`。模型拆分原话明确提供的品牌、货品名与规格，程序执行读取、校验、查询和预览。图片按附件顺序识别并复用图片入库逻辑。

按钮点选和快捷预览跳过意图识别。确认卡和系统客户选择按服务端已存选项执行，开放追问选项由模型结合前文整理。另报新单时显示普通录单清单，核对缺项时继续显示之前未答的问题。提示词版本为 `a1-agent-v4`，自动检查覆盖 Harness、本地留出题和 S6 文字账例。

| 触发 | 固定清单 |
|---|---|
| 改草稿 | 看懂意思 → 读当前草稿 → 整理进草稿 → 核对缺项 → 汇报 |
| 回复待答问题 | 看懂意思 → 按你的回答改草稿 → 核对剩下的问题 → 汇报 |
| 图片 | 在整理前插入逐张识别和合并，纯图片回合在合并后直接核对 |
| 查询 | 看懂意思 → 查取货清单 → 回答 |
| 出预览 | 看懂意思 → 核对必填项 → 算金额生成预览 → 等你确认出单 → 出单完成 |
| 改草稿同时出预览 | 共用识别一步，按顺序执行。有待确认问题时跳过预览段 |
| 其他 | 看懂意思 → 回答或请你说清楚 |

`plan` 一次保存所有步骤，`step` 保存步骤 ID、状态和实际结果，`end` 保存用时。小程序发送后先显示本地转圈，再按事件还原工作卡。确认出单由小程序调用既有接口，按正式单的来源预览恢复勾选。继续修改或草稿修订变化后，旧预览确认步骤显示已跳过。写入仍校验会话、草稿 ID 和修订。每账号同时最多一轮，回合仍有 60 秒时限和 8 次工具调用上限。重启恢复、中断和撤销复用 010 的表，无新迁移。
