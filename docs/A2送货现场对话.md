## 工作清单与核对卡

| 场景 | 固定清单 |
|---|---|
| 改实收、补价、准备送达 | 看懂你的意思 → 读本趟送货单 → 核对变更与预计应收 → 等你确认保存或送达 → 已更新送货单 |
| 回答追问 | 看懂你的意思（点选时为已收到你的选择）→ 按你的回答核对送货单 → 算预计应收 → 等你确认保存或送达 → 已更新送货单 |
| 只读查询 | 看懂你的意思 → 查本趟送货与取货进度 → 回答 |
| 其他请求 | 看懂你的意思 → 回答或提醒操作方式 |

自由文字先经 JSON 意图识别。改单时，模型只生成候选或追问；点击选项可跳过意图识别。服务端核对客户、行、单位和数字出处，按整数分试算。少收可用差量表达，整行拒收实收为零，不要求补价。仍有实收大于零的缺价货品时列出名称，不给确认送达按钮。整店收齐保留当前实收，不重置成原订数量。已锁定的账、原单未有货品和下一趟新订货不能通过 A2 改写。

## 接口与一致性

- `POST /v1/agent/turns` 只写对话记录：意图、追问、回复和 `delivery_proposal`。`GET /v1/agent/conversation` 在本趟已出单时附带最新送货进度。查询由服务端按当前数据回答。
- `POST /v1/trips/{tripId}/sheets/{sheetId}/delivery/apply` 校验账号、当前趟、正式版本、配送修订、行归属和锁单状态。传 `turnId` 时还校验卡片未处理且提交与卡片一致。多行改动、送达状态、配送修订及 `delivery_applied`／清单终态在同一事务写入；请求编号相同且内容不变时重放原结果。取消只写对话终态。另一个页面先改单后，旧卡片不能覆盖新数据。
- `POST /v1/agent/transcription` 在已登录的草稿和送货模式均可用，校验录音前后仍为同一草稿 ID 和修订。转写进输入框供修改，不自动发消息。旧草稿转写接口、送货页原有逐行接口及确认接口保留。详见[本地联调](S5本地联调.md#a2-送货现场对话)。

## 安卓三分钟验收

预先用测试号与隔离试用库准备一趟：一店水饺原订 5 箱、单价空，已确认出单。在安卓打开该店的「送货」详情 → 点「去助手语音改单」，确认输入框带出店名 → 录「水饺只收三箱，八十二块五一箱」，结束后检查并发送转写。核对卡应显示 5 → 3 箱、从待补价到 ¥82.50、预计应收 ¥247.50；点「去送货单细看」时确认仍未保存。返回助手点「保存并确认送达」，复核送货已锁定 ¥247.50，取货仍为原订 5 箱。再回助手确认旧卡不能重复操作。按[同网联调](S5微信试用.md#单账号同网联调)准备真机可访问的 API。
