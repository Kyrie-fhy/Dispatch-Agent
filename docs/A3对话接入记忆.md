## 行为说明

### 回合内自动认人

助手只处理还没有选定客户、且带有称呼的草稿客户单。正式店名或已记叫法经空白、全角 ASCII 和大小写归一后精确命中唯一一家时，草稿客户直接写成正式店名并保存客户 ID，改动行显示「老王 → 王记餐饮（记住的叫法）」或「王记餐饮：认出熟客」。卡片同时提供「不是他」。

对不上、只是子串相似或撞名时保持待选店，不自动关联。`GET /v1/agent/memory` 的 `mentions` 分别返回 `new_customer`、`candidate_only` 或 `ambiguous`，有候选时列出正式店名。撞名指同一个叫法既是 A 店的已记叫法、又是 B 店的正式店名。

### 选店、新建与「不是他」

- **选店。** 选店卡可选已有客户，并勾选「记住这个叫法」（默认勾上）。选择成功时返回 `remembered: true` 并把叫法写入熟客档案；若叫法与其他客户的正式店名相同，选店本身仍成功，返回 `remembered: false` 和 `rememberIssue: "name_conflict"`，页面提示该叫法没有记住。叫法已属于另一客户时按显式换绑处理。
- **新建。** 选择新建后客户 ID 为 `null`，后续回合即使模型补上名字也不再自动认人，也不再出选店问题。
- **不是他。** 选「不是他」会解除当前客户单的关联，保留原叫法并回到待处理状态；同一客户单后续只改明细时不会再次自动关联。

### 并入同一家与合并口径

回合中新报的称呼唯一对到草稿里已有的客户单，且两边没有同款或相似明细时，整单并入已有客户单并标记 `merged: true`，不新增客户单。

已有同款或相似明细时返回 `409 customer_merge_review`，由人选择：

- **追加新增明细**（`merge: "append"`）：本轮明细全部并入已有客户单。
- **同款保留原明细**（`merge: "keep_existing"`）：只并入不重复的明细，原有同款明细保持不变。

### 沿用单价

认人只负责归属客户，不写价格。缺价行仍为 `null`，由 `GET /v1/agent/memory` 给出 `exact_match`、`unique_variant_match`、`ambiguous_variants`、`no_match` 或 `unresolved_customer`。精确命中和唯一款附带最近一次不同成交价 `previousDistinctPrice`；多规格或多个不同历史价只列候选。

页面逐行显示「沿用」，整屏可「全部沿用」。`POST /v1/agent/price-adopt` 在写事务内重新读取历史并校验：精确价或上一不同价可接受，多规格必须同时提交品牌和规格；草稿已变化返回 `409 price_suggestion_changed`，价格不在历史中返回 `409 price_not_suggested`。

## 接口

| 方法和路径 | 请求与成功返回 | 主要错误 |
|---|---|---|
| `GET /v1/agent/memory?draftId={草稿}` | 返回 `{draftId, revision, confirmed, customers: [{id, name}], mentions: [{draftCustomerId, resolution}], prices: [...]}`。`resolution.status` 为四档认人结果；`prices` 为缺价行建议。 | `400 invalid_id`；`404 draft_not_found` |
| `POST /v1/agent/customer-choice` | 传 `{requestId, draftId, revision, draftCustomerId, choice}`。`choice` 为 `existing`（加 `customerId`、`remember?`、`merge?: "append"｜"keep_existing"`）、`new` 或 `unlink`（加 `spoken`）。成功返回 `{revision, remembered, rememberIssue?}`。 | `400 invalid_customer_choice`；`404 draft_customer_not_found`／`customer_not_found`；`409 customer_already_linked`／`customer_not_linked`／`customer_merge_review`／`draft_changed`；`429 agent_busy` |
| `POST /v1/agent/price-adopt` | 传 `{requestId, draftId, revision, lines: [{draftCustomerId, lineId, unitPriceCents, variant?: {brand, spec}}]}`。成功返回 `{revision, adopted}`。 | `400 invalid_price_adopt`；`409 price_suggestion_changed`／`price_not_suggested`；`429 agent_busy` |
| `GET /v1/customer-aliases` | 返回 `{aliases: [{alias, normalizedAlias, customerId, canonicalName}]}`，按正式店名和归一化叫法排序。 | `401` 未登录 |
| `POST /v1/customer-aliases/unbind` | 传 `{requestId, alias}`，返回 `{removed: {customerId, alias, normalizedAlias}｜null}`。 | `400 invalid_customer_alias`；相同请求重试返回首次结果，换内容复用请求编号返回 `409 request_conflict` |

选店、沿用价格和解除叫法都沿用工作区行锁与 `request_results`；相同请求重试返回首次结果。

## 运行说明

固定样本不需要密钥，配置隔离 PostgreSQL 后执行：

```sh
npm run eval:a3
```

真实模式先 `source ~/.config/dispatch-agent/env`，确认工位 B 未同时运行真实模型，再执行：

```sh
DISPATCH_A3_EVAL_LIVE=1 npm run eval:a3
```

题库位于 `tests/fixtures/a3-memory-cases.cjs`，固定模式直接使用每题给出的 `edit_draft` 操作；真实模式用 `configuredAgentModel` 和 `configuredIntentModel(..., 'A')`，每个场景跑 3 次。Harness 为每个场景创建独立隔离库，逐轮读取草稿和 `GET /v1/agent/memory` 判定，并单独累计错认店与错带价红线。[隔离 PostgreSQL 配置](S5本地联调.md#5-运行集成检查) · [熟客记忆接口](S5本地联调.md#a3-熟客记忆)
