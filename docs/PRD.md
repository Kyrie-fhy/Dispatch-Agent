# Dispatch Agent 开发 PRD

2026-11-16｜已细化 S1 手动录单、S2 多客户配送与 S3 对账。操作和验证状态见 [S1 验收](S1验收.md)、[S2 验收](S2验收.md)与 [S3 验收](S3验收.md)。S4～S8 按阶段细化。

## 1. 产品与需求来源

面向一人完成录单、取货、送货和收款的速冻食品配送员。目标为安卓微信小程序，第一份完整原型在 S4 交付。总体功能、业务规则和扩展优先级以[需求分析文档](需求分析文档.md)为总览，以[项目访谈记录](Dispatch%20Agent%20项目访谈记录.md)的已确认规则为准。

本文件补充可执行细节，避免复制全部需求正文。原始分析和技术调研保留为背景材料。需求冲突先标出来源与差异，按用户当前指令或访谈已确认规则处理。

## 2. 页面和阶段

| 页面 | S3 可用操作 | 后续增量 |
|---|---|---|
| 助手 | 选择已有客户或新建，同趟多客户手动录入、样例、整趟预览及确认、开始下一趟 | S4 模拟聊天与追问，S6 文字 Agent，S7 图片和语音 |
| 取货 | 查看当前趟取货汇总和该趟最近一次更正的数量差异 | S5 验证服务端数据一致性 |
| 送货与对账 | 按客户检查明细和配送状态，核对账目、补录旧欠、跨单收款，查看及更正历史单，导出客户图 | S4 用模拟助手调用送达、改单和收款操作 |

第 3～7 节记录 S1 和 S2 的阶段行为。客户归属、历史单操作和更正对账以[第 8 节](#8-s3-对账与跨单收款)为准。

## 3. S1 输入和校验

| 字段 | 输入行为和规则 |
|---|---|
| 客户 | 必填，输入显示名称，确认时去除首尾空格；本阶段不要求先建档 |
| 货品、品牌、规格、单位 | 必填文本；单位可手填箱、袋等，默认箱；确认时去除首尾空格 |
| 数量 | 当前实施范围为正整数箱/袋，拒绝零、负数、小数及非数字 |
| 单价 | 元，必须大于零，最多两位小数；换算为整数分计算 |
| 金额 | 明细数量乘单价，各明细加总。超出安全整数范围时提示，禁止出单 |

正整数数量与正单价是 S1 演示范围选择。若真实业务存在半箱或赠品，需补充需求后扩展。S1 的客户和货品信息直接随单保存。S3 增加用于本地跨单收款的客户 ID，S4 接入模拟别名和历史查价，S5 接入账号数据隔离。

## 4. 操作与状态

1. 首次打开创建空草稿，包含一条空明细。每次编辑保存本地草稿，保存失败时保留页面输入并提示。
2. 添加明细生成新明细 ID，移除时至少保留一条。填入验收样例将当前草稿替换为客户 A、安井水饺 500g、2 箱、82 元。
3. 点击预览先保存当前输入并校验。缺字段或金额不合法显示具体提示，正式单列表不增加。
4. 预览列出客户和每条货品、数量、单价、金额、合计。返回修改后再次预览；任何编辑使旧预览失效。
5. 点击确认使用预览对应草稿 ID 和 revision。草稿版本已变化时要求重新预览；成功后生成正式快照并显示确认结果。
6. 重复确认同一草稿返回已有正式单，不增加订单。已确认草稿不能继续覆盖正式单。
7. 开始下一张生成新的草稿 ID，历史正式单保留。
8. 重新进入恢复活动草稿与正式单；读取到未知格式或损坏数据时提示并保留原值。重置演示需在弹窗中确认，会清除本机演示草稿和订单。

S1 的正式单显示订单金额。配送状态和已送达应收到 S2/S3 实现，不能把订单金额当成已送达应收或已收款。

## 5. 异常与验收

校验错误可直接编辑纠正。写入失败时保持原有正式数据，允许重试。旧草稿写入或旧预览确认被拒绝，提示重新打开或重新预览。开发者应能从标准案例和自动检查定位原因。

金额、确认状态和重试由自动检查覆盖。操作步骤及微信模拟器与安卓真机的实际证据见[S1 验收](S1验收.md)。

## 6. 后续规则处理

S3 的同日欠款排序和已送达明细更正见第 8 节。S5 前明确收款录错、超额收款、历史分配重排，并选定后端和数据库。S6 确定文字模型与工具接口。S7 确定真实材料样本、识别服务及可接受效果。具体时点沿用[开发里程碑](Dispatch%20Agent%20开发里程碑.md)。

## 7. S2 多客户取货与送货

配送员从助手手动整理一趟订单，确认后拿着取货清单到仓库，再按客户送货。现场变更由配送员决定，通过更正正式单记录结果。业务规则源自访谈 Q17～19、Q25、Q28～35；实现范围沿用开发里程碑 S2。[访谈](Dispatch%20Agent%20项目访谈记录.md) · [开发里程碑](Dispatch%20Agent%20开发里程碑.md) · [S2 验收](S2验收.md)

### 7.1 整趟录入和出单

1. 助手页保留一张活动的新趟草稿，首次从一位客户、一条货品开始。配送员可添加或移除客户与货品。活动草稿至少保留一位客户，每位客户至少保留一条明细。样例按钮填入 A/B/C 整趟草稿。
2. 客户按首次录入位置排列，改名或改货品时位置保留。同名客户以各自的单据标识区分。删除后重新添加排在末尾。字段与金额沿用第 3 节，整趟合计也须在整数分安全范围内。
3. 「预览整趟」校验每位客户及其明细，错误定位到客户和对应字段。任一客户未补齐时，所有客户保留在草稿中。预览显示各客户货品、客户小计和整趟合计，返回编辑后须重新预览。
4. 确认后一次保存整趟正式单和各客户单据，初始为第 1 版，各明细为「未配送」。重复确认同一草稿返回同一趟。预览过期时提示重新预览。写入失败显示重试提示，正式页面继续显示原结果。
5. 配送员可在确认结果中点「开始下一趟」创建空草稿。取货与送货页仍显示最近出单的一趟，下一趟正式出单后才切换。原趟和每条明细的配送状态原样保留。S2 的历史入口提供查看和导图，配送状态更新与更正入口在当前正式趟。

### 7.2 取货与送达

| 入口 | 页面行为 |
|---|---|
| 取货 | 只汇总当前正式趟的所有货品明细，按货品、品牌、规格、原单位分组并合计数量。字段去除首尾空格后精确匹配。不同客户的单价和送达状态均不影响取货数量；箱和袋不换算。无正式趟时提示从助手出单。 |
| 送货与对账 | 先列出当前趟客户，点开查看货品、品牌、规格、数量及原单位、单价、行金额、客户订单金额和配送状态。可查看历史正式趟。 |
| 送达操作 | 单条可在「未配送」「已送达」之间切换。「本客户全部已送达」只更新当前客户的明细。保存成功后刷新状态，失败时保留旧状态并可重试。来回切页或重开后仍显示已保存状态。 |

S2 的金额标签统一使用「订单金额」。对账时从已送达明细计算本次应收，收款及欠款展示在 S3 实现。取货页提供汇总查看；仓库缺货或客户少收后，仍有有效明细的客户可走单据更正。整位客户取消留待后续定义。

### 7.3 正式单更正

1. 从当前趟的客户详情点「更正单据」，编辑该客户的正式版本副本。支持改数量、单价，新增货品，或替换和移除未配送明细。每位客户仍须有至少一条明细。更正预览显示客户、原版与新版的字段差异、各受影响明细的送达状态、新小计和取货数量差异。退出更正可回到原单。
2. 用明细标识对应原行。同一货品只改数量或单价时保留该行的送达状态，预览提示保留结果。新增明细和替换未配送明细时，新行初始为「未配送」。更换货品、品牌、规格或单位均视为替换。已送达明细的替换和移除见 [S3 更正规则](#84-更正与一致性)。
3. 现场原订 5 箱、实际只收 3 箱时，把数量改为 3 箱，确认后按整条标记「已送达」。如果更正前已标「已送达」，确认后仍为「已送达」，数量更新为 3 箱。
4. 确认时核对更正草稿和它所依据的正式版本及配送状态。基础数据或更正内容有变化时，提示核对最新数据后重新预览。成功后以同一趟和客户标识保存新版，整趟版本加一，保留前版快照供追溯。重复确认返回已保存的更正结果。取消、失败或未确认时，原正式版本、取货和可导出的单据保持原值。
5. 送货详情、取货和导图均使用同一最新版。取货页展示最近一次确认更正的差异及版本，新增或移除的汇总项按 `0 → 新数量` 或 `原数量 → 0` 展示。只改价格时显示「本次取货数量无变化」。

### 7.4 客户明细图片

从正式客户详情点「导出明细图」。图中包含所选客户、客户单据标识、该趟正式版本、货品、品牌、规格、数量与原单位、单价、每行金额和客户订单金额。长文本换行，超出单图可读尺寸时按完整明细行分页。每页标有客户、单据标识、版本和页码，末页保留客户合计。不同客户的明细各自生成。

用户可预览实际生成的图片并保存到相册，然后自行在微信发送。生成失败时提示重试，相册保存失败时保留可预览的图片并提示原因，重新保存时能核对是否全部成功。更正确认后从客户详情重新导出新版。已保存的旧图保留原版本标识。

### 7.5 数据关系与实施选择

- 一趟正式单对应一组有序客户单据。客户单据与明细都有稳定标识，草稿和每个正式版本分别保存。明细送达状态按稳定标识记录，切换状态只更新配送记录，单据版本随确认更正递增。
- 当前取货数量和更正差异分别根据最新正式快照、最近一次确认更正前后的快照计算。跨页面刷新读取同一份状态。沿用本地整体写入，保存成功才更新正式视图。未确认的新趟与更正编辑分别处理。
- S1 的已确认单据各自作为一趟历史单保存，保留客户、明细、金额和时间，配送状态标为「未记录」。未确认草稿可继续录入，其内容可扩充为多客户。迁移失败时保留原数据，错误或未知版本提示重试或联系开发者。重置仍需用户明确确认。
- 本阶段采用首次手动录入顺序、最新正式趟作为默认工作对象、当前趟手动更正和按客户导图。对账和收款在 S3；助手定位原单、模拟多输入和语音批量送达在 S4。以上阶段选择按当前文档记录，业务依据仍以原访谈为准。

## 8. S3 对账与跨单收款

配送员在「送货」核对实际交付、录入每次收到的金额，并查看钱抵到了哪些单据。当前与历史客户单均可补款或更正。S3 使用微信本地数据，仍沿用助手、取货、送货三个页面。按客户最早欠款优先、已结清单可更正及更正多收由配送员处理，源自访谈 Q36～42。下文的客户选择、确定性排序与送达更正操作是 S3 实施决定。[项目访谈记录](Dispatch%20Agent%20项目访谈记录.md#对账补款与历史单更正) · [开发里程碑](Dispatch%20Agent%20开发里程碑.md) · [S3 验收](S3验收.md)

### 8.1 客户与账目归属

- 助手页每位客户可选择已有客户，或输入名称并明确新建。预览显示选中的客户，正式确认时保存关联。客户 ID 在多趟之间复用；客户单据 ID 区分每一张正式单，显示名称随单保存。选择时显示可辨识的客户编号及最近单据。同名可分别新建，单靠名称不自动归并。同趟再次选到同一客户时，提示回到该客户单添加货品。
- 升级保留 S1/S2 的草稿、正式版本及配送状态。历史单首次启用对账时由配送员选择已有客户或新建；未关联单据可查看、导图，确认归属后才参与该客户的账目。迁移不推断过往收款；S1 的「未记录」须先由配送员明确核实为「未配送」或「已送达」。已有收款或补录欠款的归属修正留待后续定义。

### 8.2 核实配送与金额

1. 在当前或历史客户单点「开始对账」。列出仍未配送或未记录的明细。漏标的在原单补标，确未送达的保留「未配送」。核实后确认对账，记录这张客户单已核对。退出可稍后继续，已保存的配送状态仍可查看。
2. 金额使用整数分。订单金额取正式单全部明细；本次应收只加总已送达明细；本单累计实收为分配给本单的款项之和。本单剩余欠款为 `max(应收 − 实收, 0)`，多收为 `max(实收 − 应收, 0)`，分别展示。未核对单的账目预估标为「待核对」，确认后进入可收款范围。
3. 当前单展示同一客户其它已核对单及补录旧欠款的剩余欠款，标为「历史欠款」。查看历史单时该项标为「其他单据欠款」。整趟分别汇总本次应收、本单实收、本单欠款、多收及历史欠款，历史余额按客户 ID 去重，排除本趟各单；未核对客户显示核对进度及待核对金额。整趟核对完可从助手开始下一趟，未付欠款随客户保留。
4. 已核对单若要改送达状态，确认前显示目标行的新状态和应收、实收、欠款或多收的差异。确认后同步更新配送与账目，已有收款仍归原单。未核对的历史单在欠款详情中可打开继续核对，已核对和未核对有可见区分。

### 8.3 补录旧欠款与收款分配

| 操作 | 行为 |
|---|---|
| 补录旧欠款 | 从客户对账详情进入。输入发生日期、当前未付金额和可选来源，确认后生成一笔独立期初欠款。日期使用当地日历，金额须大于零且最多两位小数。重复确认或相同客户的同日期、同金额、同来源记录有防重提示；确属两笔可用不同来源区分。补录金额作为起始债项，后续可查询剩余余额。 |
| 录入本次收款 | 从已核对的当前或历史客户单打开「记收款」，输入大于零且最多两位小数的本次收到金额。收款针对该客户，欠款范围是其已核对且尚欠款的正式客户单与已补录旧欠款，顺序与打开哪张单无关。 |
| 确定顺序 | 按原单首次确认时间及补录发生日期归入本地业务日，从早到晚。同日已知原单时间的按完整时间先后；仅有日期的补录项排当日有时刻的单之后；时刻相同或都只有日期时用持久化的单据 ID 升序。更正时间、补录操作时间与页面排序均不改变原单顺序。 |
| 预览并确认 | 逐笔抵扣，每笔上限为该单剩余欠款。预览显示客户、收到金额、逐单分配及分配后余额；预览期间无正式记录。当金额超过可分配总额，显示当前可抵扣金额，整笔保留在输入状态。零欠款无可提交的分配。 |
| 保存与重试 | 确认时重新核对关联客户、金额和相关账目。分配所依据的单据、配送、收款或欠款已变更时，提示重新预览。同一提交 ID 重试返回原结果。新的同额收款可在核对最新余额后用新提交 ID 记录。一笔收款与所有分配一次提交，保存失败保留输入和原账，重试可只入账一次。 |

已分配金额保存到单据 ID，保留收款 ID、实际收到金额、时间以及每条分配。客户详情可查看关联的收款与去向。S3 的原型仅支持金额在欠款范围内的正确录入，收款录错、超额款登记、退款与历史分配重排按后续阶段处理。

### 8.4 更正与一致性

- 当前和历史客户单沿用「更正单据 → 预览 → 确认」。同一货品改数量或单价保留配送状态。替换已送达货品时，新行须明确选择「已送达」或「未配送」，预览显示原行移除及新行状态。删除已送达明细时，预览明确该行将退出应收。每张单仍保留至少一条明细。新增或替换未配送行初始为未配送。已核对单的更正预览同时展示各未配送项供核实，确认即按预览中的新状态更新账目。
- 订单金额、配送状态、取货差异、客户导图与应收均以确认后的新版为准。更正历史趟只更新该历史趟，当前取货清单继续对应当前趟。价格更正按实际同一批货核算，今后新货的新价格通过新单录入。
- 已收款及既有分配均挂在原客户单据 ID 上。应收从 ¥200 改为 ¥220 时，原已收 ¥200、本单欠 ¥20；应收改为 ¥180 时，原已收 ¥200、显示多收 ¥20，既有分配仍可追溯。以后新收款按各笔实际剩余欠款重新确定可分配范围，多收金额单独展示。
- 更正预览包含应收、实收、欠款或多收的前后数值。确认前核对该单的版本、配送状态、收款分配和预览输入；过期需重做。重复确认只生成一版。取消、写入失败及迁移失败保留原正式状态。合计及每项余额均须在整数分安全范围内。
