# S2 多客户配送验收

2026-11-15｜以下为 S2 的验收步骤和标准结果。样例来自开发里程碑。[S2 开发 PRD](PRD.md#7-s2-多客户取货与送货) · [开发里程碑](Dispatch%20Agent%20开发里程碑.md)

## 1. 基础输入与结果

在微信开发者工具导入项目并编译，从助手页重置演示后按 A、B、C 顺序录入。主流程至少从空白手动建客户和货品走通一次；「填入验收样例」可用于重复验证单项。更正与异常用各自的基础数据副本，避免前一项结果混入。

| 客户 | 品牌、货品、规格 | 数量 | 单价 | 明细金额 | 客户订单金额 |
|---|---|---:|---:|---:|---:|
| 客户 A | 安井水饺 500g | 2 箱 | ¥82.00/箱 | ¥164.00 | ¥164.00 |
| 客户 B | 安井水饺 500g | 3 箱 | ¥80.00/箱 | ¥240.00 | ¥300.00 |
| 客户 B | 安井水饺 500g | 3 袋 | ¥20.00/袋 | ¥60.00 | |
| 客户 C | 三全水饺 500g | 1 箱 | ¥75.00/箱 | ¥75.00 | ¥75.00 |

基础订单金额合计为 **¥539.00**。整趟取货为**安井水饺 500g 5 箱、安井水饺 500g 3 袋、三全水饺 500g 1 箱**，共三行。「三全」为样例中另一品牌的录入值。

## 2. 主流程

| 编号 | 操作 | 标准结果 |
|---|---|---|
| S2-01 | 在助手页录入 A/B/C，先留空 C 的品牌，点击「预览整趟」，再补为三全并重新预览。 | 先提示 C 的缺项，三位客户均留在草稿。补齐后按 A/B/C 顺序显示 ¥164.00、¥300.00、¥75.00，整趟 ¥539.00。确认前取货和送货页无新增正式结果。 |
| S2-02 | 返回编辑 C，将单价改为 ¥76.00 后再改回 ¥75.00；重新预览并确认，快速重复点击。 | 编辑后须重新预览。只新增一趟第 1 版正式单，内含三个客户单据和四条未配送明细。进入取货查看三行标准结果，A 和 B 的箱单价不同仍合计为 5 箱。 |
| S2-03 | 在送货页对 A 点击「本客户全部已送达」；在 B 的箱明细上标记送达，切回未配送，再标回已送达。 | 只有 A 和 B 的箱明细显示已送达，B 的袋及 C 保持未配送。客户金额与取货数量不变。切页及退出重进后状态保持。 |
| S2-04 | 在 B 客户详情导出并保存第 1 版图片。在 B 的更正入口将箱数量从 3 改为 2，先取消一次，再重复编辑和预览。 | 原图只有 B 的两条货品及 ¥300.00 小计。预览显示 B 箱数 3 → 2，保留已送达；B 小计 ¥300.00 → ¥220.00，整趟取货安井箱数 5 → 4。取消和未确认时原单、取货和导出数据均维持第 1 版。 |
| S2-05 | 确认 B 的更正，重复点击后在送货及取货页核对。 | 整趟只增至第 2 版，原趟及客户标识保持。B 箱明细为 2 箱 × ¥80.00 = ¥160.00，仍已送达；袋明细为 3 袋 × ¥20.00 = ¥60.00，仍未配送。B 为 ¥220.00，整趟 ¥459.00。取货三行分别为 4 箱、3 袋、1 箱，仅安井箱数显示 5 → 4。 |
| S2-06 | 从 B 的详情重新导出并保存图片，核对前后两张图。 | 新图标识第 2 版，显示 B 的 2 箱、3 袋、各行金额和 ¥220.00 小计。旧图仍标识第 1 版且为 ¥300.00。两张图均只含客户 B。 |
| S2-07 | 点击「开始下一趟」。录入一位客户的安井水饺 500g、7 箱、¥79.00，先预览再确认；查看历史。 | 录入和预览期间取货仍显示上一趟的 4 箱、3 袋、1 箱。下一趟确认后取货只有安井 7 箱，送货页新趟金额 ¥553.00。历史入口可查看上一趟第 2 版、其原有配送状态及导出 B 的图片；送达和更正操作位于当前趟。 |

## 3. 异常与回归

| 编号 | 操作 | 标准结果 |
|---|---|---|
| S2-08 | 新趟预览后改字段，或更正预览后改变相关配送状态再触发旧确认；分别模拟新趟确认、送达保存和更正确认写入失败。 | 旧预览要求重新核对。写入失败有可见反馈，原订单、版本、取货与配送状态保持。恢复写入后重试只产生一次状态变化或一个新版本。 |
| S2-09 | 基础样例中只将 A 的价格从 ¥82.00/箱 改为 ¥80.00/箱并确认。 | A 为 ¥160.00，整趟 ¥535.00，原配送状态保留。取货仍为三行，提示「本次取货数量无变化」。 |
| S2-10 | 在独立副本把 C 的未配送三全水饺替换为安井水饺，规格、单位及数量保持；在另一副本尝试替换或移除已送达明细。 | C 的替换行仍未配送；取货变为安井 6 箱、3 袋，差异为安井箱 5 → 6、三全箱 1 → 0。已送达明细的替换和移除有明确提示，原正式单保持。 |
| S2-11 | 另建一条 5 箱 × ¥82.00 的未配送明细，模拟客户只收 3 箱，先把数量改为 3 并确认，再标记送达。 | 金额由 ¥410.00 更正为 ¥246.00，取货数量 5 → 3，整条明细可标为已送达。同一案例若更正前已经标为已送达，更正确认后仍保留该状态。 |
| S2-12 | 在单个客户下录入 40 条明细，含需换行的长品名，导出图片。分别模拟生成失败、相册权限拒绝和部分图片保存失败。 | 所有行均可读且没有截断。分图时页码齐全，所有图片标明客户和版本，末页金额正确。失败提示与结果一致，权限恢复后可保存未完成部分。 |
| S2-13 | 以 S1 本地数据启动 S2，包含确认单、未确认草稿，以及单独的损坏数据样例。 | 每张旧正式单独立出现在历史中，金额和明细保持，配送状态显示「未记录」。未确认草稿可补录客户，已确认草稿不重复生成订单。损坏数据及迁移失败时保留原始存储。 |
| S2-14 | 在独立副本录入两位同名客户；用不同规格、带首尾空格的相同品名、箱与袋验证取货。 | 同名客户单据、送达状态和导图互相独立。只差首尾空格的相同四字段合并，不同规格、品牌或单位分行。 |

## 4. 验收记录要求

- 本地与 CI 分别记录类型检查、构建、文档链接、业务规则及模拟页面事件结果，自动检查覆盖整趟确认去重、四字段汇总、明细状态隔离、更正联动以及失败恢复和 S1 数据迁移。
- 微信开发者工具从三个正常页面入口走 S2-01～07，核对真实 WXML、页面跳转、重开恢复和图片渲染。其他异常按可复现环境记录。
- 安卓真机核对输入与键盘、长单可读性、实际保存到相册及权限拒绝后的恢复。记录版本、机型、微信版本和步骤。手动发送可用自有聊天核对，保留图片及操作结果。S2 记录本轮可验证结果，目标机导出与手动分享按里程碑在 S7 补齐。
