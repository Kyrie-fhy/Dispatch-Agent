## 本地会话接口

按 [S5 本地联调](S5本地联调.md)启动隔离测试库。服务端配置 `DISPATCH_WECHAT_APP_ID` 和 `DISPATCH_WECHAT_APP_SECRET` 后启用微信会话，启动日志显示「微信会话」。缺少其中一项时启动失败。本机模式未设置两项时使用开发账号 `a` 和 `b`。试用模式要求两项均有效。

`POST /v1/session/wechat` 接收 `{"code":"客户端 wx.login 返回的临时凭证"}`。响应为 201，只返回项目自己的 `token` 和 `expiresAt`。用 `Authorization: Bearer <token>` 请求 `/v1/workspace` 取得活动草稿和当前正式趟。`DELETE /v1/session` 撤销该凭证。服务按 AppID 和 OpenID 分开保存账本。启用微信会话后，开发登录入口关闭，原开发凭证无法使用。微信 `session_key` 无须保存。

凭证无效时，客户端重新调用 `wx.login` 并用新凭证登录。遇到微信频率限制或服务错误时，显示对应提示。接口仍使用本地监听。

## 正式页面本机联调

1. 以测试号 AppID 和对应 AppSecret 启动本机服务。用 `npm run build:s5` 构建后在微信开发者工具重新编译，进入「配送工作区」。本机默认 API 为 `http://127.0.0.1:8787`。如改用其他端口，在构建时设置 `DISPATCH_MINIPROGRAM_API_ORIGIN`。本机 HTTP 联调在开发者工具的本地测试配置中关闭域名校验。手机试用需要配置 HTTPS 合法域名并打开校验。
2. 点「微信登录」，手动录入客户和货品。点「保存草稿」，或点「预览整趟」先保存再预览。预览后点「确认生成正式单」。在「取货」和「送货单」查看当前正式趟。开始下一趟后仍可查询上趟的取货和送货单，直到新趟正式确认。
3. 退出并重新微信登录，核对草稿、修订号、正式单版本和金额。页面只在当前会话内持有凭证。退出时立即清空页面并尝试撤销凭证，可在登录页重试撤销失败的会话。上一会话的晚到响应不会进入新会话。
4. 保存失败时可重试原请求。发现服务器草稿已更新时，页面同时显示当前输入和服务器草稿。对同一未确认草稿，可选择使用服务端版本，或确认以当前输入覆盖最新版本。

用 `npm run build` 返回 S4 演示构建。S5 正式页支持本趟正式单及配送状态查询，配送写入、对账和更正页面仍待接入。

## 手机验收

1. A 登录后保存含可辨认客户名的草稿，并确认一趟订单。退出后重新进入，核对草稿 ID、修订号和正式单版本。
2. B 登录应进入自己的账本。确认 A 的草稿和正式单无法被 B 读取或修改。切换账号时，从上一账号发出的请求即使晚到也不得覆盖当前页面。
3. 下线会话后，用原凭证请求工作区应返回 401。重新取得微信凭证后应能恢复同一账号的记录。真机同时检查 HTTPS 请求没有依赖跳过域名校验。
4. 登录和恢复验收完成后，再验证材料上传中断恢复、材料归属和过期识别结果。
