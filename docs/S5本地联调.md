# S5 本地草稿服务联调

本轮验证两个本地测试账号独立保存草稿、重启后恢复以及冲突处理。服务使用 PostgreSQL 18，仅监听 `127.0.0.1`。微信小程序暂时仍运行 S4 预览。

## 1. 初始化数据库

用本机 PostgreSQL 的管理员账号创建独立数据库 `dispatch_local` 和普通登录角色 `dispatch_local`。把下面的连接地址换成自己的本地配置。

```sh
npm ci
export DISPATCH_DB_ADMIN_URL='postgresql://postgres:管理员密码@127.0.0.1:5432/dispatch_local'
npm run db:migrate
psql "$DISPATCH_DB_ADMIN_URL" -c 'GRANT dispatch_app TO dispatch_local'
```

**通过标准**　输出「PostgreSQL 迁移已完成」。重复执行迁移保留现有数据。

## 2. 启动本地服务

```sh
export DISPATCH_DB_URL='postgresql://dispatch_local:本地账号密码@127.0.0.1:5432/dispatch_local'
npm run serve:local
```

**通过标准**　输出「S5 本地草稿服务已启动 http://127.0.0.1:8787」。服务启动时要求使用普通数据库账号。

## 3. 用测试账号拿到草稿

1. 向 `POST /v1/session/development` 发送 JSON `{"account":"a"}`，响应为 201，包含 `token` 和过期时间。换成 `b` 可获取另一个账号的凭证。
2. 向 `GET /v1/workspace` 发送 `Authorization: Bearer <token>`，响应中的 `draft` 包含服务器分配的 `id`、`revision` 和 `customers`。A、B 的草稿 ID 各不相同。
3. 向 `PUT /v1/drafts/{id}` 发送带凭证的 JSON，包含请求编号 `requestId`、上一版 `revision` 和编辑后的 `customers`。保存成功后修订号加一。
4. 重启服务，用同一测试账号重新登录，再获取工作区。该账号上次保存的客户和修订号仍在。换成另一个账号的凭证访问原草稿 ID，读取和更新均返回 404。
5. 请求 `DELETE /v1/session` 后，原凭证访问草稿返回 401。

## 4. 运行集成检查

`DISPATCH_TEST_ADMIN_URL` 应指向本机测试 PostgreSQL 的管理员数据库。检查会创建带随机名称的临时库及普通角色，结束后清理。

```sh
DISPATCH_TEST_ADMIN_URL='postgresql://postgres:管理员密码@127.0.0.1:5432/postgres' npm run test:server
```

| 检查 | 通过标准 |
|---|---|
| 账号隔离与恢复 | A、B 分别保存并重启恢复。API 不返回其他账号的草稿，数据库行权限也限制读取和更新。退出后原凭证失效 |
| 并行、重试与回滚 | 同版并行保存只有一笔成功。相同请求重试返回第一次结果，改内容后复用编号返回冲突。故意让第二次数据库写入失败时，草稿保留原版，恢复后可重试 |
