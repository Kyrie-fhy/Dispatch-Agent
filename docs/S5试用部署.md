# S5 HTTPS 试用部署

本页用于准备异地试用。现役状态和已验证范围见[开发任务](开发任务.md#当前交付)。同网手机预览按 [S5 微信试用](S5微信试用.md#单账号同网联调)操作。

手机经 `wx.request` 访问已备案并解析到 Linux 主机的 HTTPS 域名。Caddy 终止 TLS，只将 `/v1/*` 转发给监听 `127.0.0.1:8787` 的 API。两种部署方式共用微信登录、数据库最小权限和本机健康检查。

主机需能访问微信登录接口，并允许 Caddy 所需的入站 HTTPS 和证书验证流量。数据库端口和 API 端口留在内网或回环。使用中国大陆云资源时，先核对域名备案和接入状态。[Caddy 自动 HTTPS](https://caddyserver.com/docs/automatic-https) · [腾讯云首次备案](https://cloud.tencent.com/document/product/243/37402)

## 1. 构建和迁移

按目标分支的迁移目录增量升级再启动服务。当前 `main` 需迁移到 010，使用 A1 四标签配送 MVP 和 `a1-agent-v5` 固定工作清单。回测历史 S7d 表单版 `58cea3f` 时使用迁移 009 的隔离库。安卓主流程的试用证据对应 `2c52066`，见 [A1 阶段记录](A1对话录单.md#改版验证结果)。异地试用的分支和验收状态见[开发任务](开发任务.md#远端与试用)。

在主机准备 Node.js 22、Caddy 和 `dispatch` 系统用户。将要试用的提交放到 `/opt/dispatch-agent/current`，以具备该目录写权限的部署用户构建。

```sh
npm ci
npm run build:server
npm prune --omit=dev
```

### 方式 A　单机轻量云同装 PostgreSQL + 每日自动备份（低成本推荐）

在 API 所在主机安装 PostgreSQL 服务与同主版本客户端，令 `listen_addresses` 仅包含回环（例如 `localhost`），修改后重启 PostgreSQL。确认 `pg_hba.conf` 的 TCP 回环规则为 `scram-sha-256`，并保留供本机 `postgres` 系统用户使用的 Unix socket `peer` 认证。用管理员建库。以下以新装实例的 `postgres` 为迁移账号，`\password` 提示中输入密码。

```sh
sudo -u postgres psql -X -d postgres
```

```sql
CREATE DATABASE dispatch_trial;
\password postgres
```

将迁移连接写入 root 所有、权限 `0600` 的 `/etc/dispatch-agent/migrate.env`。运行账号在迁移后创建，运行连接写入 `/etc/dispatch-agent/trial.env`。用户名或密码中的 URL 特殊字符需要百分号编码。

```dotenv
# migrate.env
DISPATCH_DB_ADMIN_URL=postgresql://postgres:编码后的迁移密码@127.0.0.1:5432/dispatch_trial?sslmode=disable
# trial.env
DISPATCH_DB_URL=postgresql://dispatch_trial_api:编码后的运行密码@127.0.0.1:5432/dispatch_trial?sslmode=disable
```

回环连接也支持 `localhost` 和 `[::1]`。采用本机明文时，从两个环境文件移除 `DISPATCH_DB_CA_FILE`。如在本机启用数据库 TLS，改用无查询参数的连接网址，并在两个文件配置 CA 路径。运行时校验证书，即使回环 URL 写了 `sslmode=disable`。

### 方式 B　外接同 VPC 独立云 PostgreSQL（内网 TLS）

在同地域、同 VPC 的独立实例建立空数据库 `dispatch_trial`，允许 API 主机访问数据库内网端口。为内网地址开启 SSL，把 CA PEM 放到 `/etc/dispatch-agent/postgres-ca.pem`，并授权 `dispatch` 读取。连接网址使用与证书匹配的内网地址，写到库名为止。[腾讯云 PostgreSQL 内网连接](https://intl.cloud.tencent.com/zh/document/product/409/34626) · [腾讯云数据库 SSL](https://cloud.tencent.com/document/product/409/115986)

```dotenv
# migrate.env
DISPATCH_DB_ADMIN_URL=postgresql://迁移账号:编码后的密码@数据库内网地址:5432/dispatch_trial
DISPATCH_DB_CA_FILE=/etc/dispatch-agent/postgres-ca.pem
# trial.env
DISPATCH_DB_URL=postgresql://dispatch_trial_api:编码后的密码@数据库内网地址:5432/dispatch_trial
DISPATCH_DB_CA_FILE=/etc/dispatch-agent/postgres-ca.pem
```

### 应用迁移与授权

迁移账号需要能建 schema、表和角色，并授予迁移建成的 `dispatch_app` 角色。独立云数据库按服务商说明分配这些权限。[腾讯云 PostgreSQL 用户与权限](https://intl.cloud.tencent.com/zh/document/product/409/43242)

```sh
sudo systemd-run --wait --pipe --collect \
  --working-directory=/opt/dispatch-agent/current \
  --property=EnvironmentFile=/etc/dispatch-agent/migrate.env \
  /usr/bin/env DISPATCH_SERVER_MODE=trial /usr/bin/node code/server-dist/server/migrate.js
```

迁移成功后，以管理员连接 `dispatch_trial`，创建独立运行账号并授予 `dispatch_app`。用 `\password` 设置运行密码。运行账号及其角色成员关系须通过启动权限检查，禁止管理员、`BYPASSRLS`、`CREATEROLE` 和业务表 owner 权限。

```sql
CREATE ROLE dispatch_trial_api LOGIN;
\password dispatch_trial_api
GRANT dispatch_app TO dispatch_trial_api;
```

## 2. 启动 API 和 HTTPS 代理

新建 root 所有、权限为 `0600` 的 `/etc/dispatch-agent/trial.env`，按数据库方式填入运行账号连接，然后加入试用 AppID 和对应的 AppSecret。

```dotenv
DISPATCH_WECHAT_APP_ID=试用小程序AppID
DISPATCH_WECHAT_APP_SECRET=同一个AppID的AppSecret
```

安装 API 单元。

```sh
sudo install -m 0644 deploy/s5/dispatch-s5.service /etc/systemd/system/
sudo systemctl daemon-reload
```

方式 A 在启用 API 前用 `sudo systemctl edit dispatch-s5` 添加下列 drop-in。将 `postgresql.service` 替换为本机实际的 PostgreSQL unit，例如 `postgresql@17-main.service`。API 基础单元在启动失败后每 5 秒重试，数据库就绪后通过启动角色检查并开始监听。[systemd.service](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html)

```ini
[Unit]
Wants=postgresql.service
After=postgresql.service
```

启用服务并检查启动结果。

```sh
sudo systemctl enable --now dispatch-s5
curl --fail-with-body http://127.0.0.1:8787/healthz
```

本机健康检查返回 `200` 和 `{"status":"ready"}`，表示服务已通过运行角色检查，且能读取迁移后的工作区表。其他返回可用 `sudo journalctl -u dispatch-s5 -n 50` 查看启动情况。

将 [Caddy 配置模板](../deploy/s5/Caddyfile) 的 `dispatch-api.example.com` 替换为实际域名，加入 `/etc/caddy/Caddyfile`。模板为转发请求设置回环 Host，保留 API 的本机 Host 检查。

```sh
sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
sudo systemctl reload caddy
```

在云主机外验证入口，以下命令中的域名替换为实际地址。依次预期 `401`、`400`、`404`、`404`，分别说明工作区需凭证、微信登录接口可达、开发账号登录关闭、本机健康检查未转发。

```sh
curl -sS -o /dev/null -w '%{http_code}\n' https://dispatch-api.example.com/v1/workspace
curl -sS -o /dev/null -w '%{http_code}\n' -H 'Content-Type: application/json' -d '{}' https://dispatch-api.example.com/v1/session/wechat
curl -sS -o /dev/null -w '%{http_code}\n' -H 'Content-Type: application/json' -d '{"account":"a"}' https://dispatch-api.example.com/v1/session/development
curl -sS -o /dev/null -w '%{http_code}\n' https://dispatch-api.example.com/healthz
```

## 3. 备份与恢复

### 方式 A　每日逻辑备份

从部署目录安装[备份脚本](../deploy/s5/backup-postgres.sh)。脚本以同机 `postgres` 系统用户经 socket 运行 `pg_dump -Fc`，保留 RLS 下的完整数据。目录为 `0700`，归档为 `0600`，校验可读取归档目录后发布文件。按 UTC 日期每天保留一份，重复执行沿用当日归档。清理本数据库满 14 天的归档。[pg_dump](https://www.postgresql.org/docs/current/app-pgdump.html)

```sh
sudo install -m 0755 deploy/s5/backup-postgres.sh /usr/local/bin/dispatch-backup-postgres
sudo install -d -m 0700 -o postgres /var/backups/dispatch-agent
sudo -u postgres /usr/local/bin/dispatch-backup-postgres dispatch_trial /var/backups/dispatch-agent
```

将下列内容写入 root 所有、权限 `0644` 的 `/etc/cron.d/dispatch-agent-backup` 并启用 cron。每日按系统时区 02:15 执行。按发行版调整客户端工具的 `PATH` 和 PostgreSQL socket 目录（必要时设置 `PGHOST`）。

```cron
PATH=/usr/local/bin:/usr/bin:/bin
15 2 * * * postgres /usr/local/bin/dispatch-backup-postgres dispatch_trial /var/backups/dispatch-agent
```

恢复先用同主版本工具写入独立空库。新集群先创建 `dispatch_app NOLOGIN` 和普通运行账号并授予该组。以下示例把归档名替换为要恢复的日期，恢复保留 ACL 和 RLS。[pg_restore](https://www.postgresql.org/docs/current/app-pgrestore.html)

```sh
sudo -u postgres createdb -T template0 dispatch_trial_restore
sudo -u postgres pg_restore --single-transaction --no-owner --dbname=dispatch_trial_restore \
  /var/backups/dispatch-agent/dispatch_trial-2026-11-18.dump
```

核对恢复库的迁移记录和数据后，将两个环境文件的库名切换为恢复库。若代码版本有新迁移，按第一节补齐。重启 API，检查 `/healthz`，用同一试用微信账号核对草稿、正式单与账目。

### 方式 B　独立实例备份与恢复

在云数据库控制台开启每日自动备份，并按试用安排设置保留期。恢复时从目标快照或时间点克隆实例，核对迁移、数据与最小权限账号。目标实例加入 API 所在 VPC，为新内网地址配置 SSL，更新两个环境文件的地址、库名和 CA，再按第一节检查迁移。重启 API 后验收健康检查、微信登录和账目。[腾讯云自动备份设置](https://cloud.tencent.com/document/product/409/68388) · [克隆实例](https://cloud.tencent.com/document/product/409/68277)

## 4. 小程序试用

在该 AppID 的微信后台配置 `request` 合法域名，保持开发者工具域名和证书校验开启。为配送 MVP 配置实际的 HTTPS API 地址，用有预览权限的微信账号完成[异地 HTTPS 验收](S5微信试用.md#异地-https)。

```sh
DISPATCH_MINIPROGRAM_API_ORIGIN=https://dispatch-api.example.com npm run build
```

将示例地址替换为实际已备案域名，在开发电脑执行构建。微信开发者工具导入 `code/dist` 并使用与 API 配置相同的 AppID 编译、生成预览二维码。手机切到移动网络扫码，验证登录、录单保存、预览确认和重登恢复。

验收文字、图片和语音时，在 API 的运行环境配置 `DISPATCH_TEXT_MODEL_KEY`。订单材料的操作和验收见[图片录单](S7a图片录单.md)及[录音转写](S7b语音录单.md)。复测 S5 对账和收款工作区时，使用相同的 HTTPS origin 运行 `npm run build:s5`。异地验证进度见[开发任务](开发任务.md#远端与试用)。

双账号验收时补查两个账号的预览权限，再按[隔离用例](S5微信试用.md#双账号隔离)测试。若使用另一个 AppID，服务端同步切换到对应 AppSecret。账本按 AppID 与 OpenID 隔离，切换 AppID 后从独立试用数据开始。

## 本机验收记录

2026-11-18，单机部署适配在隔离 PostgreSQL 17.4 验证。`npm run test:server` 26 项通过，覆盖回环无 CA、显式 CA 下保留 TLS、跨机无 CA 拒绝、非法 URL 拒绝及试用接口边界。实际执行迁移及 API 启动入口，管理员运行角色被拒绝，普通 `dispatch_app` 登录角色经回环使 `/healthz` 返回 `200`，使用模拟微信配置。备份脚本实测目录和归档权限、同日重跑、过期归档清理、失败临时文件清理及恢复 009 迁移记录和测试数据。已验证 S4、S5、默认配送 MVP 和示例 HTTPS origin 构建。目标 Linux systemd、cron、正式证书与微信异地真机待验收。

2026-11-16，以试用模式在隔离的 PostgreSQL 17.11 实例运行迁移，普通服务角色启动后本机健康检查返回 `200`。`pg_stat_ssl` 显示 API 连接使用 TLS 1.3。换用其他 CA 后，试用 API 无法启动。另通过 30 项业务与页面检查、13 项本机服务端检查及 S5 HTTPS 地址构建检查。逻辑备份恢复由 GitHub CI 的 PostgreSQL 作业执行。

Caddy 2.11.9 校验部署模板通过。本机用临时测试证书和回环端口运行相同的转发规则。客户端校验证书后访问四个 HTTPS 探针，依次收到 `401`、`400`、`404`、`404`。Linux systemd 启动、腾讯云内网连接、正式证书签发和双微信账号真机仍待在目标环境验证。
