# S7a 图片录单

在配送 MVP 的「录单 → 图片材料」从微信聊天或相册选图。等上传完成后点「识别到草稿」，成功时回到录单页，核对原件、补齐缺项，再走已有的预览和人工确认。识别未完成时可在材料页重试，或回录单页手工填写。分批材料按点击识别的先后进入同一草稿。

## 运行和验收

1. 按 [S5 本地联调](S5本地联调.md)配置隔离 PostgreSQL，运行 `npm run db:migrate`，应用 `008_image_order_inputs.sql`。按 [S6 本机配置](S6文字录单.md#启动和验收)将 `DISPATCH_TEXT_MODEL_KEY` 注入服务进程。图片使用 `deepseek-flash`，文字继续使用 S6 模型设置。
2. 运行 `npm run build:s6`，在微信开发者工具重新编译。真机用测试号，按 [单账号同网联调](S5微信试用.md#单账号同网联调)从独立预览目录扫码。
3. 分别用聊天订单截图和手写单原图验收。对照原件逐项核对货品、品牌规格、数量、单位和单价。截图中的语音气泡和手写单缩略图略过，原图可作为独立材料。未写单价时保留空值。
4. 同一趟重选同一张图，核对识别状态为「已整理」。回录单修改草稿，另一张已上传图片仍可手动提交识别。核对识别成功只生成草稿，预览后需再点确认才生成正式单。

每张上传上限 10 MiB，识别接受 JPEG、PNG、WebP，每张最多整理 64 行。手写单按从左到右逐列整理。货品名看不清但数量可读时，先保留数量，把名称留空待补。HEIC 可保留为材料，识别前需转存为 JPEG 或 PNG 后上传。[DeepSeek Vision](https://api-docs.deepseek.com/guides/vision/)

## 服务边界

`POST /v1/image-orders` 使用工作区凭证，接收 `{requestId, draftId, revision, materialId}`，成功返回 `{draft}`。服务只读取归属当前账号和当前趟、已完整上传并校验的图像。调用模型时，用户消息只包含图片和提取指令。模型只提出待人工核对的新明细，沿用 S6 业务校验。相同客户、货品的不同单位保留为不同明细。

服务在模型返回后重新检查会话和草稿修订，写草稿、写入图片摘要和保存请求结果在同一事务中完成。同一趟按图片字节摘要去重。同版重试可恢复原成功响应。重新上传同字节的图片会显示「已整理」。上传所关联的草稿修订保留原值。
