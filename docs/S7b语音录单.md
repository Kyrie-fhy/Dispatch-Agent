# S7b 录音转写

在配送 MVP 的「录单 → 录音转文字」开始录音。选图后也可在「图片材料」边看所选图片边录。点「结束并转写」，结果回到文字框，可编辑，再点「整理到草稿」。已有文字会保留，转写接在下一行。整理后的明细继续走预览与人工确认。

录音单段最多 60 秒。微信按单声道、16 kHz 录 PCM，小程序封装成 16 位 PCM WAV 后发送。麦克风授权被拒后可打开设置重新授权。遇到系统中断或小程序切到后台，回前台后重新录音。转写服务或网络故障时，可在当前页面用原录音重试。草稿更新、录音文件失效时重新录入。退出后从上次已保存的草稿恢复。

## 启动和验收

1. 按 [S5 本地联调](S5本地联调.md)启动隔离 PostgreSQL。把 `DISPATCH_TEXT_MODEL_KEY` 配置在服务端，运行 `npm run serve:local`。用 `npm run build:s6` 构建配送 MVP 并在微信开发者工具编译。手机扫码使用 [同网预览](S5微信试用.md#单账号同网联调)。
2. 录入「给老王送两箱安井水饺，每箱八十二元」。核对转写中的货品、品牌、数量、单位和单价。修改其中一个字段后提交整理，检查草稿收到编辑后的内容。对照草稿修订，转写结束时修订保持原值，整理成功后递增一次。
3. 首次拒绝麦克风权限，核对提示后从设置开启。录音时切后台或被系统通话打断，恢复后重新录制。转写前断网，再连网后用原录音重试。手机验收时记录输出 WAV 格式、调用耗时和人工修改。

## 服务边界

`POST /v1/drafts/{id}/transcription` 使用工作区凭证、`X-Draft-Revision` 和 JSON `{wave}`，其中 `wave` 为完整 WAV 的 Base64 编码。服务也接受 `audio/wav` 二进制请求。服务校验单声道 16 位 PCM WAV、音频时长和 8 MiB 音频上限。音频以 multipart 的 `file` 字段发给 DeepSeek，返回 `{draftId, revision, text}`。模型前后重新校验会话、当前趟和草稿修订。录音与转写仅在处理请求和当前页面时使用，草稿由下一次文字整理请求写入。现有材料上传仍用于图片。[DeepSeek Speech to Text](https://api-docs.deepseek.com/guides/asr/)
