# S7c 混合录单

图片、手输文字和可编辑的语音转写共同补齐当前趟草稿。沿用 S7a 图片识别、S7b 转写和 S6 文字整理接口。图片先形成待核对明细。补充文字时，服务把当前草稿明细与新文字一同交给文字模型。补充只能写入能唯一定位的缺失字段。已填内容如果需要改动，直接在明细中编辑并保存。

## 同网真机验收

按 [S7b 启动和验收](S7b语音录单.md#启动和验收)配置 DeepSeek、微信测试号和隔离 PostgreSQL，用当前分支构建配送 MVP。按 [单账号同网联调](S5微信试用.md#单账号同网联调)生成预览码。

1. 在安卓手机的「录单 → 图片材料」选一张测试图。图上只写「老王：安井水饺 2 箱」，留空规格和单价。上传后点「识别到草稿」，核对只生成一行，待补齐里有规格和单价。
2. 在文字框输入「老王的安井水饺是 500g」，点「录音转文字」，说「每箱八十二元」。核对转写追加在已有文字后面，检查并编辑再点「整理到草稿」。原明细应保留 2 箱，补齐规格 500g 和单价 ¥82。若仍提示确认同名客户，请在客户编辑区选择已有客户或明确新建，再预览 ¥164。点击确认后才生成正式单，取货应为 2 箱。
3. 用同一测试账号的第二个会话做并发复测。发起材料处理后延迟模型回包，在第二个会话把同一行数量改为 3 箱并保存，再释放回包。处理中的会话应看到最新数量和核对提示。另测第二个会话先确认并开始下一趟，再释放旧趟回包，核对新草稿和旧正式单。
4. 在目标安卓短屏上核对选图、录音、文字补充和待补齐列表。记录材料类型与数量、逐字段预期和实际值、补改次数、各次调用耗时和可取得的用量。固定账例通过后，再用未参与开发的实际配送材料核对。

## 草稿变化后的恢复

图片整理、语音转写和文字整理都以草稿 ID 和修订为准。因同趟草稿变化而收到冲突时，页面读取最新草稿，保留同趟原文和已登记图片，用户核对后可重新提交。过期录音需重新录制。存在未保存的明细时，页面保留本地修改，展示最新草稿供用户核对。服务已换趟时，页面载入新趟并清空旧趟文字和所选图片，旧图仍在原材料记录。
