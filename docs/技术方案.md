# Dispatch Agent 当前技术方案

2026-11-15｜实际工程为微信原生小程序 + TypeScript，从零实现业务层。

## 1. 已采用的结构

- code/miniprogram/pages 为三个微信页面，处理输入与展示。
- code/miniprogram/core/orders.ts 是纯 TypeScript 业务模块，负责草稿、版本、金额、校验和正式确认。
- code/miniprogram/services/orders.ts 用微信本地存储实现 StoragePort，当前存储键为 dispatch-agent-s1-v1。
- tests 为 Node 内置测试执行的业务检查与页面事件模拟。
- scripts/build.cjs 编译 TypeScript、复制 WXML/WXSS/JSON，并检查页面资源。
- code/dist 是导入微信工具的运行产物，不提交 Git。微信配置位于根目录 project.config.json。

页面调用业务服务，业务服务校验并通过存储接口写入，成功后页面才展示完成。没有后端、远端数据库或真实 AI 调用。三个页面使用微信基础组件和共享 WXSS，当前不引入 UI 框架。

## 2. 数据接口

| 类型或操作 | 含义 |
|---|---|
| Draft | id、revision、客户显示名称和 ItemInput 数组；输入以字符串保存，允许尚未填完 |
| Order | 确认时快照，包含明细整数分金额、总金额和确认时间 |
| State | schemaVersion=1，活动草稿及正式单列表 |
| StoragePort | read() 读取未知数据，write(state) 一次保存完整状态 |
| save(draft) | 校验草稿 ID 与版本，保存后 revision 递增 |
| preview(draft) | 校验字段并计算金额，无正式写入 |
| confirm(id, revision) | 已确认则返回原单；否则校验版本后保存正式单 |
| startNext() / reset() | 开新草稿保留历史；显式重置演示数据 |

本地一次存储一个完整 State，保存失败抛错。它只覆盖单机演示；S5 的服务端事务、身份校验和并发处理须单独实现及验证。版本格式不兼容时拒绝静默覆盖，未来新增格式需设计迁移。

## 3. 工具链和版本

本机核验为 Node 18.15.0、npm 9.5.0、Git 2.53.0。依赖锁定 TypeScript 5.9.3、miniprogram-api-typings 5.3.1。当前本地工具链可执行全部检查；GitHub Actions 模板使用 Node 22。当前凭证缺少 workflow scope，模板暂存于 scripts/templates/github-actions-check.yml，远端未启用，尚无 CI 运行结果。

统一采用 npm 和 package-lock.json。npm ci 安装锁定依赖，npm run check 执行类型、构建、业务/页面事件检查和文档链接检查。S1 无运行时第三方依赖。

TypeScript 在本地由 tsc 编译到 CommonJS JavaScript 后导入微信工具，避免同时依赖两套 TypeScript 编译。微信官方也提供内置 TypeScript 插件，本项目当前采用外部显式构建。 [微信 TypeScript 文档](https://developers.weixin.qq.com/miniprogram/dev/devtools/compilets.html)

## 4. 微信环境

当前配置 appid 为 touristappid，占位用于本地准备。用户已确认 AppID、权限和安卓手机尚未准备。本机未发现微信开发者工具，当前没有微信模拟器或真机运行证据。

环境具备后，先 npm run build，再从微信开发者工具导入项目根目录。在工具中使用自己的有效 AppID，检查代码目录指向 code/dist，个人设置保存在已忽略的 project.private.config.json；不能把访问密钥写入小程序源码。
