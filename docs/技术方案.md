# Dispatch Agent 当前技术方案

当前工程使用微信原生小程序和 TypeScript。运行状态与阶段验收见[开发任务](开发任务.md)。

## 1. 已采用的结构

- code/miniprogram/pages 为三个微信页面，处理输入与展示。
- `code/miniprogram/core/orders.ts` 负责金额、单客户字段校验和 S1 数据读取。`code/miniprogram/core/trips.ts` 实现整趟确认、配送状态、正式版本和取货差异。
- `code/miniprogram/services/orders.ts` 通过微信本地存储读写 `TripState`，沿用 `dispatch-agent-s1-v1` 键。`code/miniprogram/services/order-images.ts` 通过 2D Canvas 生成分页 PNG，并经相册 API 保存。
- tests 为 Node 内置测试执行的业务检查与页面事件模拟。
- scripts/build.cjs 编译 TypeScript、复制 WXML/WXSS/JSON，并检查页面资源。
- code/dist 是导入微信工具的运行产物，不提交 Git。微信配置位于根目录 project.config.json。

页面调用业务服务，业务服务校验并通过存储接口写入，成功后页面才展示完成。没有后端、远端数据库或真实 AI 调用。三个页面使用微信基础组件和共享 WXSS，当前不引入 UI 框架。

## 2. 数据接口

| 类型或操作 | 含义 |
|---|---|
| `TripDraft` | 整趟草稿 ID、修订号和有序客户草稿，输入以字符串保存 |
| `Trip` | 包含每次确认的正式版本，按明细 ID 另存配送状态；各版金额为整数分 |
| `TripState` | `schemaVersion=2`，一张活动草稿和正式趟列表 |
| `TripStorage` | `read()` 读未知原始数据，`write(state)` 一次保存完整状态 |
| `saveDraft` / `previewTrip` / `confirm` | 保存检查草稿 ID 和修订号；预览无正式写入；重复确认返回同一趟 |
| `setDelivery` / `confirmAmendment` | 配送按当前趟、正式版本、客户和明细定位；更正校验正式版本与配送修订号，按更正 ID 去重 |
| `startNext` / `reset` | 开新草稿时保留历史；用户确认后才能重置演示数据 |

S1 数据读验后迁移。旧正式单进入只读历史，配送状态为未记录；未确认草稿保留。读入损坏数据会报错并保留原值。取货清单从最新正式版本计算，最近一次更正差异从前后两个版本计算。本地一次保存完整状态，保存失败时页面保留原有正式结果。S5 另行实现服务端事务、身份校验和并发处理。

## 3. 工具链和版本

`package.json` 要求 Node ≥ 18.15.0。依赖锁定 TypeScript 5.9.3、miniprogram-api-typings 5.3.1。GitHub Actions 使用 Node 22，工作流 `.github/workflows/check.yml` 在推送和 PR 更新时执行 `npm ci` 与 `npm run check`。

统一采用 npm 和 package-lock.json。npm ci 安装锁定依赖，npm run check 执行类型、构建、业务/页面事件检查和文档链接检查。S1 无运行时第三方依赖。

TypeScript 在本地由 tsc 编译到 CommonJS JavaScript 后导入微信工具，避免同时依赖两套 TypeScript 编译。微信官方也提供内置 TypeScript 插件，本项目当前采用外部显式构建。 [微信 TypeScript 文档](https://developers.weixin.qq.com/miniprogram/dev/devtools/compilets.html)
