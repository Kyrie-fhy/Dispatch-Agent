# Dispatch Agent 当前技术方案

当前工程包括微信原生小程序和独立的 Node.js／TypeScript API，服务端使用 PostgreSQL。交付状态与验收入口见[开发任务](开发任务.md)。

## 1. 已采用的结构

- S4 演示使用 `code/miniprogram/pages` 下的助手、取货和送货与对账页面。S5 工作区和配送 MVP 使用 `pages/workspace`，通过 `services/workspace.ts` 调用工作区 API。`services/materials.ts` 负责本机文件暂存和分块续传。
- `code/miniprogram/core/orders.ts` 负责金额、单客户字段校验和 S1 数据读取。`code/miniprogram/core/trips.ts` 实现整趟确认、配送状态、正式版本、取货差异和账目写入。`code/miniprogram/core/settlement.ts` 计算应收、旧欠款余额和收款分配，并验证本地账目数据。
- `code/miniprogram/services/orders.ts` 通过微信本地存储读写 `TripState`，沿用 `dispatch-agent-s1-v1` 键。`code/miniprogram/services/order-images.ts` 通过 2D Canvas 生成分页 PNG，并经相册 API 保存。
- `code/miniprogram/core/mock-assistant.ts` 解析固定样例、整理待补充项、按客户 ID 查价和找正式单。`services/mock-materials.ts` 模拟异步识别。正式操作仍由订单和对账服务预览、检查及确认。
- `code/server` 的 HTTP API 监听回环地址，复用小程序业务层的金额、客户选择和取货规则。基础接口与启动方法见 [S5 本地联调](S5本地联调.md)，模型接入见本页第 2.3 节。
- `tests` 包含业务和页面事件检查，`tests/server` 运行 HTTP 与 PostgreSQL 的集成检查。

S4 通过业务层写微信本地存储，S5 工作区和配送 MVP 由服务端保存。入口均在保存成功后展示完成。小程序使用微信基础组件与共享 WXSS。

## 2. 数据接口

### 2.1 微信本地原型

| 类型或操作 | 含义 |
|---|---|
| `TripDraft` | 整趟草稿 ID、修订号和有序客户草稿，输入以字符串保存 |
| `Trip` | 包含每次确认的正式版本，按明细 ID 另存配送状态；各版金额为整数分 |
| `TripState` | `schemaVersion=3`，活动草稿、正式趟、客户、客户与单据的关联、补录欠款、收款记录，以及可选的助手附加信息 |
| `TripStorage` | `read()` 读未知原始数据，`write(state)` 一次保存完整状态 |
| `saveDraft` / `previewDraft` / `confirm` | 保存检查草稿 ID 和修订号，预览校验客户选择与货品，重复确认返回同一趟。预览不写入正式单或客户关联 |
| `setDelivery` / `confirmDelivery` / `confirmAmendment` | 配送与更正按原趟、版本、客户单及明细定位。已核对单变更时先预览账目；更正校验正式版本、配送修订号和本单实收，按更正 ID 去重 |
| `linkCustomer` / `reviewSheet` | 显式关联客户并标记对账完成。历史「未记录」明细须先明确配送状态 |
| `confirmOpening` / `confirmReceipt` | 提交同一笔操作可重试；收款及其分配在一次写入中保存。收款确认前重算相同客户账目，基础数据变化时要求重新预览 |
| `startNext` / `reset` | 开新草稿时保留历史；用户确认后才能重置演示数据 |

S4 在同一存储结构增加可选的助手信息。草稿变更、重复记录、数量追问和本次确认的客户别名在同一次写入中保存。材料队列和处理记录只留在本次页面会话；队列按发送顺序执行，每个任务在开始处理时绑定草稿 ID 和修订号，异步结果返回前已修改、换趟或重置则不写入。已有版本无需迁移助手信息。

S1 和 S2 数据在校验后升级。原正式版本、活动草稿和配送状态保留，S1 旧单的配送状态为「未记录」。历史单首次对账时由用户选择客户归属。读入损坏数据会报错并保留原值。取货清单从当前趟最新正式版本计算，更正差异从该趟前后两个版本计算。本地一次保存完整状态，保存失败时页面保留原有正式结果。

### 2.2 S5 PostgreSQL 服务

本地测试账号通过服务端会话确定归属，客户及订单表的外键包含账号 ID。数据库行权限限制在当次事务的账号范围内，测试用普通数据库角色验证这层权限。

- `001_drafts.sql` 建立会话、账号工作区和请求结果。按草稿修订号保存，事务持有账号工作区行锁，同账号内相同的请求编号与内容返回第一次成功结果。
- `002_formal_trips.sql` 增加预览、客户、配送趟、正式版本和客户单关系。预览关联草稿 ID 与修订号。确认时保存版本快照、客户关联、初始配送状态及请求结果，整个事务一起提交或回滚。
- `003_delivery_review.sql` 保存按账号和客户单隔离的配送预览，并授权服务角色更新配送状态、配送修订号和核对标志。配送写入和核对检查正式单版本及配送修订号；核对后的配送变更须使用服务端预览。同一请求的写入与结果记录在同一事务。
- 客户单通过共用业务规则从已送达明细计算本次应收，从该单的分配记录计算实收。确认配送变更时也会校验预览时的实收。
- `004_receipts.sql` 增加期初欠款、收款、分配和账目预览。分配绑定账号、客户以及对应的正式客户单或期初欠款。收款确认复查账目后，在同一事务写入收款、每条分配与请求结果。服务端按 `Asia/Shanghai` 计算业务日，并沿用原单首次确认时间排序。
- `005_amendments.sql` 按账号、配送趟和客户单保存更正预览。确认时复查版本、配送修订号和账目，在一个事务中追加正式快照、写入新版配送状态并记录请求结果。预览 ID 对应唯一正式版本，原分配继续关联客户单据 ID。
- `006_materials.sql` 按账号保存材料、原草稿修订和私有文件分块。新图片登记在页面和 API 使用同一扩展名规则，具体格式见[材料上传接口](S5本地联调.md#10-材料上传和续传)。上传登记用工作区行锁校验当前修订，分块提交锁住材料行。已收到的分块可按原位置重试，最后一块与完整文件摘要校验在同一事务提交。
- 配置 AppID 和 AppSecret 后，本地服务可经 `code2Session` 建立微信会话。内部身份使用 `wechat` 和 `AppID:OpenID`，仍复用账号、工作区和凭证表。会话请求校验当前运行的身份类型与 AppID。配置和试用验收见 [S5 微信试用](S5微信试用.md)。
- 工作区保留当前正式趟的引用。开始下一趟时创建空草稿，上一趟仍可查询。取货按正式版本汇总，不读取草稿。

### 2.3 DeepSeek 模型接入

项目采用 DeepSeek 作为模型服务。S6 默认用 `deepseek-flash` 的 Chat Completions JSON 输出整理文字。`007_text_order_inputs.sql` 保存按账号和草稿隔离的输入摘要，用于重复检测。配置、草稿写入约束和真实调用评测见 [S6 文字录单](S6文字录单.md)。

S7a 用 `deepseek-flash` 识别已上传的整张图片。`008_image_order_inputs.sql` 按账号、草稿和图片摘要去重，写入草稿和登记摘要在同一事务中。格式、手机操作和识别偏差见 [S7a 图片录单](S7a图片录单.md)。

S7b 使用 DeepSeek `POST /v1/tools/asr` 转写整段录音。小程序用微信录制 16 kHz 单声道 PCM，封装为 WAV，以 Base64 随 JSON 发送。服务解码并校验完整性后提交给模型。转写填入可编辑文字框，用户提交后复用 S6 整理。模型前后校验登录会话、配送趟和草稿修订。页面另外检查本地录单文字，避免旧结果覆盖用户输入。[语音边界与验收](S7b语音录单.md) · [DeepSeek Speech to Text](https://api-docs.deepseek.com/guides/asr/) · [微信录音 API 类型](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)

转写模型返回可编辑文字，文字和图片模型返回待核对的结构化明细。预览、正式确认与金额由业务代码和用户操作驱动。

## 3. 工具链和版本

`package.json` 要求 Node ≥ 18.15.0。依赖锁定 TypeScript 5.9.3、miniprogram-api-typings 5.3.1。GitHub Actions 使用 Node 22，工作流 `.github/workflows/check.yml` 在推送和 PR 更新时执行 `npm ci`、`npm run check`，再用 PostgreSQL 18 运行 `npm run test:server`。

`npm ci` 安装锁定依赖，`npm run check` 执行类型检查、构建、业务及页面事件检查和文档链接检查。当前小程序没有第三方运行时依赖。

小程序各构建命令均输出到 `code/dist`，默认启用配送 MVP。具体命令见 [README](../README.md#微信预览)。服务端经 `npm run build:server` 编译到 `code/server-dist`。[微信 TypeScript 文档](https://developers.weixin.qq.com/miniprogram/dev/devtools/compilets.html)

## 4. 微信环境

S4 演示页面的数据存于微信客户端本地。工作区页面在内存中持有会话凭证，退出时清空页面数据，后续登录使用新会话。待续传文件暂存在小程序的本机目录，按草稿和材料匹配，续传前核对当前账号下的服务端进度。项目导入和构建切换见 [README](../README.md#微信预览)，验收状态见[开发任务](开发任务.md#当前交付)。
