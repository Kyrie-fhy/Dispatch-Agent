## 5. 授权失败的准确情况

本地 gh 已登录 Kyrie-fhy。交接时 gh auth status 显示 scope 为 gist、read:org、repo，缺 workflow。不要输出或索取 token。

此前 gh auth refresh --hostname github.com --scopes workflow 发起了两次设备授权。用户最后完成了网页授权，但 CLI 进程以如下连接错误退出。

```text
Post "https://github.com/login/oauth/access_token": dial tcp ...:443: i/o timeout
```

两个旧设备代码都不应继续使用。旧进程已经结束，没有可继续等待的有效授权进程。

系统代理检查发现 macOS 已启用 HTTP、HTTPS、SOCKS 代理，地址均为 127.0.0.1:7897。CLI 进程未发现 HTTP_PROXY、HTTPS_PROXY 或 ALL_PROXY 环境变量。推断 CLI 可能未走浏览器使用的系统代理，但代理是否能解决问题尚未验证。之前两个 curl 诊断会话在工具上下文变更后不可再访问，没有保存可用于下结论的成功结果。

下一步建议只为单条命令设置代理，不修改用户全局网络配置。先确认本地代理仍启用、端口仍有效，然后验证 GitHub OAuth 地址可连通，再重新发起授权。重新授权若确有需要，应说明上次网页成功而 CLI 回包失败的原因。
